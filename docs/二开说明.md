# 二开说明

这份文档面向**要继续改这个插件的人**（包括未来的自己）。读完应该能做到：

- 知道改哪个函数、为什么改那里
- 知道怎么验证改动真的生效了（而不是「看着好像行」）
- 知道哪些坑踩过了、别再踩一遍
- 上游发新版本时知道怎么把定制恢复回来

---

## 0. 先搞清楚：这个仓库是什么

**是**：上游 `main.js` / `styles.css` 的**打包产物**，加上一套**可重放的补丁脚本**。

**不是**：源码 fork。

原因是上游（Calendar Hub）只发布编译后的 `main.js`，仓库里没有可以直接改的 TypeScript 源码
（我们的网络环境也拉不到它的构建链）。所以这里的做法是：

```
上游原版 main.js/styles.css
   │
   ├─ 手工改出想要的效果（改的是打包产物）
   │
   ├─ 把改动抽成「片段文件」+「补丁脚本」，放进 patches/
   │
   └─ 重放验证：原版 → 跑补丁 → 与线上文件逐字节比对 + 幂等
```

**这个取舍的代价**：

- 上游一发新版本，Obsidian 更新会覆盖 `main.js` / `styles.css`，定制全丢 → **必须重跑补丁**
- 上游改了被补丁锚定的那段代码 → 补丁会报「锚点未匹配」并中止（**不会写坏文件**），需要重新侦察
- 改的是编译产物，可读性不如源码，但比想象中好（见下一节）

**好处**：不依赖上游的构建环境；补丁脚本本身是自解释的，记录了「改了什么、为什么」。

## 1. 怎么读这个打包产物

### 1.1 先确认它保留了换行

```bash
head -5 main.js
```

如果输出是多行、有缩进的 JS，就说明 esbuild 没做压缩 —— **可以按行定位**，
这是能维护的前提。如果是一整行，那这套补丁做法就不适用了。

本插件保留了换行，所以 `grep -n` 能直接给出行号。

### 1.2 用源码路径注释当路标

打包产物里保留了源码文件的分界注释：

```js
// src/view.ts
var CalendarView = class extends import_obsidian10.ItemView { ... }

// src/ui/sources/streak.ts
// src/ui/sources/tasks.ts
// src/ui/sources/noteCount.ts
// src/io/dailyNotes.ts
```

按这些注释跳转，比在 25 万字节里瞎找快得多。

> ⚠️ 注意 `// src/view.ts` 在文件里**出现两次**（一次是别的组件的分界），
> 用 `grep -n` 看全部命中再决定用哪个，别用 `findIndex` 抓第一个。

### 1.3 找运行时注入的 CSS（最容易漏的一步）

插件的一部分样式**不在 `styles.css` 里**，而是 Svelte 组件运行时塞进 `<head>` 的：

```bash
grep -n 'style.textContent = "' main.js
```

本插件一共注入 6 段，对应 6 个组件（`.day` / `.dot` / `.arrow` / `.nav` / `td` / `.container`）。
它们带编译期 hash，选择器形如 `.day.svelte-q3wqg9`。

**这直接决定你写的 CSS 能不能生效** —— 见第 6 节的坑 1。

### 1.4 找扩展点

| 想做的事 | 去哪找 |
|---|---|
| 往日历格子上加内容 | `sources` 数组 + `metadata.dataAttributes` |
| 在视图里加面板/按钮 | `CalendarView.renderMode()` |
| 加设置项 | `defaultSettings` + `CalendarSettingsTab.display()` + `writeOptions` |
| 改样式 | `styles.css`（注意第 6 节坑 1 的特异性） |
| 改日期解析 | `getDateFromFilename` / `buildNotesByDate` |

## 2. 四个定制点分别改在哪

### 2.1 日期归一化（容错非标准连字符）

**问题**：原版用 `window.moment(basename, format, true)` 严格解析文件名日期。
文件名里如果用了 U+2011（非断行连字符）之类，严格模式会失败，这些笔记被静默跳过。

**改法**：在唯一的入口 `getDateFromFilename` 里先做一次字符归一化。

```js
function normalizeDateSeparators(text) {
  return text.replace(/[\u2010\u2011\u2012\u2013\u2014\u2015\u2212\uFF0D\uFE63\u00AD\u2043]/g, "-");
}
function getDateFromFilename(basename, dailyNoteFormat, filenameDateFormat = "") {
  const normalizedBasename = normalizeDateSeparators(basename);   // ← 只加了这一层
  const exactDate = parseNoteDate(normalizedBasename, dailyNoteFormat);
  // ...后面原样不动
}
```

**为什么改这里就够了**：`buildNotesByDate` 是唯一给每日笔记建索引的地方，
而它只通过 `getDateFromFilename` 解析文件名。改一处覆盖全库。

### 2.3 日历格子上的计数徽标

**关键机制：不要自己改渲染逻辑，用 `sources` 扩展点。**

插件把每个格子的内容交给一组 source 计算：

```js
async function metadataReducer(promisedMetadata) {
  const meta = { dots: [], classes: [], dataAttributes: {} };
  const metas = await Promise.all(promisedMetadata);   // ← 注意这行，见坑 5
  return metas.reduce((acc, m) => ({
    classes: [...acc.classes, ...m.classes || []],
    dataAttributes: Object.assign(acc.dataAttributes, m.dataAttributes),
    dots: [...acc.dots, ...m.dots || []],
  }), meta);
}
function getDailyMetadata(sources, date, ..._args) {
  return metadataReducer(sources.map((source) => source.getDailyMetadata(date)));
}
```

而 `dataAttributes` 会被原样写到格子的 DOM 上：

```js
let div1_levels = [{ class: `day ${ctx[7].classes.join(" ")}` }, ctx[7].dataAttributes || {}];
set_attributes(div1, div1_data);
```

所以只要提供一个 source，往 `dataAttributes` 里塞 `data-hub-notes` / `data-hub-todos`，
再用 CSS 伪元素 `content: attr(data-hub-notes)` 画出来就行 —— **完全不用碰 Svelte 的渲染逻辑**。

```js
var hubBadgeSource = {
  getDailyMetadata: async (date) => {
    const dataAttributes = {};
    const notes = getDailyNotesForDate(date, get_store_value(dailyNotesByDate), get_store_value(dailyNotes));
    if (notes.length) dataAttributes["data-hub-notes"] = String(notes.length);
    const byDate = await getTodoBadgeByDate();          // 带 mtime 缓存，42 个格子不会读 42 次文件
    const todos = (byDate[date.format("YYYY-MM-DD")] || []).filter((it) => !it.done).length;
    if (todos) dataAttributes["data-hub-todos"] = String(todos);
    return { dataAttributes };
  },
  getWeeklyMetadata: () => Promise.resolve({ dataAttributes: {} }),
};
```

**注册**：在 `CalendarView.onOpen()` 的 `this.sources` 数组末尾加一项。
这是**唯一需要改原版代码的地方**，就一行。

**徽标是怎么画出来的**：`styles.css` 末尾的覆盖块，用 `::before` 画笔记数、`::after` 画待办数，
绝对定位到格子右上角。竖直方向用 `clamp()` 保证「两个数字绝不互相压字」（见坑 6）。

### 2.4 徽标外观做成设置项

**三处接线，缺一不可：**

| # | 位置 | 改什么 | 漏了会怎样 |
|---|---|---|---|
| 1 | `defaultSettings` | 加 8 个 `hubBadgeXxx` 字段 + 默认值 | `loadOptions` 里是 undefined，设置面板显示空 |
| 2 | `display()` 尾部 | 调 `this.addHubBadgeSettings()` | **设置面板里根本看不到这些项** |
| 3 | 新方法 `addHubBadgeSettings()` | 每个字段一段 `new Setting(...)` | — |

**消费端 —— CSS 变量桥**：设置值写进 `document.body` 的 CSS 自定义属性，样式用 `var()` 读。

```js
var HUB_BADGE_VARS = { size: "--hub-badge-size", x: "--hub-badge-offset-x", /* ... */ };
var hubBadgeUnsub = null;

function applyHubBadgeSettings() {
  const opts = get_store_value(settings) || {};
  const root = document.body.style;
  const setVar = (name, value) => {
    if (value === void 0 || value === null || value === "") { root.removeProperty(name); return; }
    root.setProperty(name, String(value));
  };
  setVar(HUB_BADGE_VARS.size, px(opts.hubBadgeFontSize, 9));
  // ...
}

function ensureHubBadgeSettingsSync() {
  if (hubBadgeUnsub) { applyHubBadgeSettings(); return; }
  hubBadgeUnsub = settings.subscribe(() => { applyHubBadgeSettings(); });   // 设置一变立刻生效
}
```

`ensureHubBadgeSettingsSync()` 挂在 `mountTodoPanel()` 的**开头、任何 early return 之前**。

**为什么空值要 `removeProperty` 而不是写空串**：让 CSS 里的 `var(--x, 兜底值)` 兜底值生效。
写空串会把变量设成非法值，`var()` 直接失败。

### 2.5 布局调整（待办横排 + 笔记瘦身）

**做法：在 `styles.css` 末尾追加一个覆盖块**，不改上面的规则。

为什么：上游升级会整体覆盖 `styles.css`，用「末尾追加 + 幂等标记」的方式，
升级后重跑补丁就恢复，而且**不需要匹配旧规则的确切文本**（那样一升级就断）。

代价：靠源码顺序覆盖（特异性相同时后写的赢），所以**这个块必须留在文件最末尾**。

**一个额外的 JS 改动**：横排之后滚轮默认是纵向的、横向滚不动，加了一段转换：

```js
list.addEventListener("wheel", (event) => {
  if (event.deltaX !== 0 || event.deltaY === 0) return;    // 不干扰横向滚轮 / Shift+滚轮
  if (list.scrollWidth <= list.clientWidth) return;         // 没溢出就完全不接管
  event.preventDefault();
  list.scrollLeft += event.deltaY;
}, { passive: false });
```

## 4. 加一个新功能的标准流程

```
1. 侦察
   ├─ grep 找到要改的函数 / 要加的扩展点
   ├─ 确认目标元素的真实类名（含 svelte hash）
   └─ grep 'style.textContent = "' 看有没有运行时注入的 CSS

2. 先在文件里改出效果（直接改 main.js / styles.css）
   └─ 改完在 Obsidian 里重载插件、肉眼确认

3. 把改动抽成片段
   ├─ 大段代码 → 单独存 patches/xxx.insert.js
   ├─ 样式     → 单独存 patches/xxx.css
   └─ 用脚本从「已改好的文件」里切出来，别手抄（容易漏字节）

4. 写进补丁脚本
   ├─ 锚点必须取「原始版本」的文本（不是当前已改过的文件！见坑 3）
   ├─ 幂等标记要逐字出现在打完补丁后的文件里（main.js 优先用代码签名，见坑 4）
   └─ 覆盖已有样式时用「末尾追加 + 就地替换」，不要 mustReplace 旧规则

5. 重放验证（不可跳过）
   ├─ 原版 → 按顺序跑全部补丁 → 与线上文件逐字节比对
   └─ 再跑一遍，确认全部 no-op

6. 真实验证
   ├─ 用插件真实 CSS + 真实 DOM 在无头浏览器里渲染
   └─ 量尺寸 / 量碰撞 / 截图，别靠肉眼
```

## 5. 怎么验证（这一节最重要）

### 5.1 用真实 CSS 做无头验证

**为什么**：插件的样式来自三处 —— 主题、`styles.css`、运行时注入的 `.svelte-*`。
自己搭 mock 写「差不多」的 CSS，会得出「改了没生效」的假结论，或者反过来把已经撞车的东西看成没问题。

```js
// 1) 把运行时注入的 CSS 抠出来
const injected = [];
mainSrc.split('\n').forEach((l) => {
  const m = /style\.textContent = "([\s\S]*?)";\s*$/.exec(l.trim());
  if (m) injected.push(JSON.parse('"' + m[1] + '"'));
});
const liveCss = fs.readFileSync('styles.css', 'utf8');
```

页面里按「主题变量 → 注入 CSS → styles.css」的顺序放，**DOM 结构要照抄，包括 svelte 类名**：

```html
<div class="container svelte-pcimu8">
  <table class="calendar svelte-pcimu8">
    <td class="svelte-egt0yd">
      <div class="day svelte-q3wqg9" data-hub-notes="3">15<div class="dot-container svelte-q3wqg9">…</div></div>
    </td>
  </table>
</div>
```

**两条环境保真度要求**（不做的话尺寸类结论全是错的）：

```html
<style>*{box-sizing:border-box}</style>   <!-- Obsidian 全局是 border-box -->
```

而且要知道：**无头 Chromium 的滚动条多为叠加式（不占布局空间），
Windows 上的 Obsidian 是实体滚动条（`scrollbar-width: thin` 约占 11px）**。
所以凡是「固定尺寸」的东西，**写死尺寸，不要靠 `align-self: stretch` 间接推导** ——
滚动条一出现高度就变了，而无头测试根本测不出来。

### 5.2 重放比对

```bash
SB=/tmp/replay
mkdir -p "$SB/.obsidian/plugins/calendar-hub" "$SB/.workbuddy/patches"
cp patches/* "$SB/.workbuddy/patches/"
cp main.js.bak-<原版时间戳>    "$SB/.obsidian/plugins/calendar-hub/main.js"
cp styles.css.bak-<原版时间戳> "$SB/.obsidian/plugins/calendar-hub/styles.css"

node "$SB/.workbuddy/patches/calendar-hub-u2011-date.patch.js"
node "$SB/.workbuddy/patches/calendar-hub-todo-panel.patch.js"
node "$SB/.workbuddy/patches/calendar-hub-layout.patch.js"

cmp -s "$SB/.obsidian/plugins/calendar-hub/main.js" main.js && echo "main.js 一致"
cmp -s "$SB/.obsidian/plugins/calendar-hub/styles.css" styles.css && echo "styles.css 一致"
```

**差一个字节都不算通过。** 补丁锚点写漏一处，产物会少几十字节、语法还是对的 ——
这种「看起来对但其实不完整」最难发现。

### 5.3 断言要具体

- 「固定尺寸」要断言**具体数值**（`Math.abs(h - 68.65) < 0.6`），不能只断言「都相等」
- 判据分**硬/软**两档：硬判据必须全过；受物理尺寸限制会必然让步的项（比如格子太矮时数字会碰到圆点）单独列为软判据
- 至少测三档宽度（窄 ~300px / 中 ~620px / 宽 ~1200px）+ 极值（超长文本、0 项、20 项）

## 6. 坑清单（都是真踩过的）

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | **运行时注入 CSS 的特异性陷阱** | 你在 `styles.css` 里写 `.day { padding: 9px }` 完全不生效，也不报错 | 注入的是 `.day.svelte-q3wqg9`（0,2,0），裸 `.day`（0,1,0）被覆盖。加祖先类提到 0,2,1：`.calendar .day` |
| 2 | **`String.replace` 吃掉 `$$`** | 产物里 `view.calendar.$.ctx` 语法错误 | 打包产物里大量 `$$.ctx`。用 `src.replace(from, () => to)` 函数形式，不做特殊序列解释 |
| 3 | **补丁锚点取自「已改过的文件」** | 从原版重放时 `锚点未匹配` 直接退出 | 锚点必须取**原始备份**里的文本。加过新方法后，原来的锚点形态在已改文件里已经不存在了 |
| 4 | **幂等标记和实际插入的文本对不上** | 重跑补丁又插了一遍，文件变大 | 标记必须**逐字**出现在打完补丁的文件里。`main.js` 优先用**代码签名**（如 `list.scrollLeft += event.deltaY`），注释会被改、代码不会 |
| 5 | **一个 source 失败整格空白** | 某个日期格子里的日期、圆点、徽标全没了 | 格子内容在 `{#await metadata}` 的 `then` 分支里，`pending`/`catch` 分支编译出来都是 `noop`。而 `metadataReducer` 用 `Promise.all`，任一 source reject 就整格空白，且**不会自己恢复**。加 source 时要保证自己不抛 |
| 6 | **`min()` 保不住「不重叠」** | 字号调大后两个数字叠在一起 | `min(Y+size+gap, 100%-size-Y)` 只保证不越界。要保证「两个数字不互相压字」得用 `clamp(下界, 理想, 上界)` —— `clamp` 在 `MIN>MAX` 时返回 `MIN`，优先级就对了 |
| 7 | **联动的值拆成两个旋钮** | 把卡片调矮，第三行被**从半截**切断 | 高度和「截断行数」是联动的。只开放「显示几行」一个变量，高度用 `calc(行数 × 行高 + 内边距)` 算出来 |
| 8 | **flex 子项漏 `min-width: 0`** | 卡片被长文本撑宽，`text-overflow` / `line-clamp` 全失效 | flex 子项默认 `min-width: auto`，加 `min-width: 0` 才能收缩 |
| 9 | **`flex-direction: column` + `align-items: flex-start`** | 标题的 `text-overflow: ellipsis` 永远不触发 | 这种组合下 span 宽度由内容决定。改成 `align-items: stretch` + 标题 `width: 100%` |
| 10 | **`max-height: 46%` 兜不住** | 待办一多就把上面的笔记区挤没了 | 百分比 max-height 在某些嵌套下解析不到，元素按自然高度撑开。决定「会不会挤压邻居」的容器**要写死像素高度** |
| 11 | **横向滚动条吃掉卡片高度** | 待办少时不出现滚动条、多了才出现，卡片高度跟着跳 11px | 卡片高度**写死**，别用 `align-self: stretch`。无头浏览器测不出来（叠加式滚动条） |
| 12 | **验证页没设 `box-sizing`** | 写 `height: 132px` 的元素量到 143px | Obsidian 全局是 `border-box`，验证页要补 `*{box-sizing:border-box}`。尺寸对不上先查这条 |
| 13 | **`rm -rf` 被沙箱拦** | 重放验证时清沙箱目录失败 | 换个新目录名（`replay2`/`replay3`…）更省事 |
| 14 | **JS 标识符不能以数字开头** | `3行可容纳: ...` → `SyntaxError` | 中文字段名可以，但别以数字开头 |

## 7. 补丁脚本怎么工作

三个补丁，**必须按这个顺序**跑（后一个的锚点来自前一个插入的代码）：

| 顺序 | 脚本 | 作用 |
|---|---|---|
| 1 | `calendar-hub-u2011-date.patch.js` | 日期分隔符归一化 |
| 2 | `calendar-hub-todo-panel.patch.js` | 待办面板 + 新增按钮 + 格子徽标 + 徽标设置项 |
| 3 | `calendar-hub-layout.patch.js` | 待办横排 + 笔记卡片瘦身 + 滚轮横滚 |

**每个补丁都做四件事：**

1. **幂等检测** —— 打过就跳过（`main.js` 用代码签名，`styles.css` 用注释标记）
2. **`mustReplace` 锚点替换** —— 锚点没匹配就**明确报错并退出**，不做任何修改（不会写坏文件）
3. **自动备份** —— `main.js.bak-<时间戳>`，出问题直接还原再重跑
4. **重放可验证** —— 从原版跑一遍必须与线上文件逐字节一致

**第 3 个补丁的样式部分是「就地替换」**：它「拥有」从自己的注释标记到文件末尾的全部内容 ——
没打过就追加，打过就替换成最新版本。所以**改了片段重跑就能升级**，同时仍然幂等
（内容一样就不写、不产生多余备份）。

> ⚠️ 约束：这个覆盖块必须留在 `styles.css` 最末尾，**不要在它后面再追加别的东西**，否则会被替换吃掉。

**出问题怎么恢复**：用 `main.js.bak-<时间戳>` 还原再重跑补丁。
**不要手工去删插重的那一段** —— 手工改的东西下次重放就对不上了。

## 8. 已知限制

### 8.1 待办文件路径写死了

`main.js` 里：

```js
var TODO_NOTE_PATH = "06 每日灵感/00 清晨方白晓-待办事项.md";
```

换成你自己的路径即可（只改这一行，改完记得重跑补丁脚本更新 `patches/*.insert.js`，
否则下次重放会覆盖回去）。

**想做得更好**：把它做成设置项（照 2.4 的「三处接线」加一个字段，
再在 `refreshTodoPanel` 里读 `plugin.options.todoNotePath` 代替常量）。

### 8.2 新增待办不会更新「索引图」

如果你的待办文件顶部有一张自动生成的热力图 / 索引图，本插件只负责读写
`## 待办事项说明` 段落，**不会**更新那张图。需要由你自己的脚本维护。

### 8.3 弹出窗口（popout）里徽标外观设置不生效

设置值写在主窗口的 `document.body` 上，popout 里 `var()` 拿不到，会回落到 CSS 兜底值。
不崩，只是回默认外观。

### 8.4 激活格上的徽标对比度偏低

选中/今天那一格是强调色背景，红色徽标在上面偏暗。想要更好的对比度可以在
`styles.css` 覆盖块里加：

```css
.calendar .day.active[data-hub-notes]::before,
.calendar .day.today[data-hub-notes]::before { color: var(--text-on-accent); }
```

## 9. 快速自查清单

改完东西交付前过一遍：

- [ ] 改动能由补丁脚本从原始版本重放出来吗？
- [ ] 重放产物与线上文件 `cmp` 逐字节一致吗？
- [ ] 补丁重复运行会 no-op 吗？
- [ ] 幂等标记逐字出现在打完补丁的文件里吗？
- [ ] 验证页设了 `*{box-sizing:border-box}` 吗？
- [ ] 用户说「固定尺寸」的东西是写死的，还是靠 `stretch` 推导的？
- [ ] 「固定」的断言断言了具体数值，还是只断言了「都相等」？
- [ ] flex 子项给了 `min-width: 0` 吗？
- [ ] 联动的值有没有被拆成两个旋钮？
- [ ] 窄宽度（~300px）和极值（超长文本 / 0 项 / 20 项）都测过吗？
- [ ] 有没有把「改了但没生效」当成「已生效」？
- [ ] 告诉用户上游升级后怎么恢复了吗？
